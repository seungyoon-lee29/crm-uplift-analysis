# 의사결정 로그

분석 중 내린 주요 선택과 *이유*. (프레임워크보다 맥락이 중요하다는 원칙대로, 왜 그렇게 했는지를 남긴다.)

### D-1. 합성 데이터 대신 실 벤치마크(Hillstrom)
인과/uplift를 합성하면 treatment 효과를 *내가 손으로 심는* 꼴 → 순환논리. 평균효과를 측정하는 EDA와 달리 인과는 조작 위험이 크다. Hillstrom은 무작위배정(control=무발송)이라 깨끗한 반사실을 제공하는 *실데이터*라서 채택.

### D-2. 모델 라이브러리 = `scikit-uplift`
가볍고 Hillstrom 로더·Qini·uplift 곡선 내장. `causalml`은 무겁고 Python 3.9 + numpy 2.0에서 빌드 리스크. → sklift.

### D-3. numpy<2 핀 (전용 venv)
시스템 numpy 2.0.2 ↔ scikit-uplift 0.5.1 비호환. 전용 venv에서 `numpy>=1.24,<2`로 격리해 `make setup` 재현성 확보.

### D-4. treatment 이진화 = (Mens+Womens) vs No-Email
"보낼까 말까"가 질문의 핵심. 이메일 종류(Mens/Womens) 구분은 2차 관심사라, 우선 *발송 여부*로 이진화. (종류별 분석은 확장 과제.)

### D-5. 금액 환산 = conversion × AOV (raw spend 아님)
raw `spend`는 분산이 매우 커(대부분 0, AOV $115) 분위별 추정이 노이즈투성이. 더 안정적인 `conversion`에 AOV를 곱해 매출 환산하고, raw spend는 robustness 부록으로만.

### D-6. 의사결정 단위 = 분위 한계분석 (누적 top-k 아님)
"누구에게 보낼까"는 *한계* 순이익>0 여부로 결정. 누적 top-k 곡선은 음의 분위를 양의 분위가 가려 의사결정을 흐린다. → 10분위 한계 순이익으로.

### D-7. 가정 파라미터는 코드가 아니라 `config`에 분리
마진·발송비·수신거부율·LTV는 데이터 밖 가정. 코드에 박으면 "숨은 결론"이 된다. `config/config.yaml`에 모아 노출하고 민감도로 다룸.

### D-8. 단일 답 대신 채널피로비 민감도
기본 가정 하나로 "타겟팅 승" 결론을 내면 가정에 숨은 임의성을 감춘다. 수신거부 비용을 축으로 *언제 답이 갈리는지*(손익분기 $0.15)를 보이는 게 정직하고 더 유용.
